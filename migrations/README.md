# 数据库表结构说明

面板的表结构有三个来源，各有用途，三处需要保持一致。

| 来源 | 什么时候生效 | 用途 |
|---|---|---|
| `gost.sql` | 全新安装时，由 MySQL 容器首次启动执行 | 创建最基础的表（用户、节点、隧道、转发等） |
| 后端启动时的建表逻辑（`springboot-backend/.../config/*SchemaInitializer.java`） | 每次后端启动 | 创建其余的表，并为老数据库补上缺少的列和索引。**正常升级靠的就是这一处** |
| 本目录下的迁移脚本 | 不会自动执行 | 需要手动维护数据库时使用，例如后端无法启动、要先把表结构补齐 |

## 修改表结构时

1. 在对应的 `SchemaInitializer` 里加上建表或补列逻辑，写成可重复执行的（表或列已存在时不报错）。
2. 如果希望这次改动也能手动执行，在本目录新增一个以日期开头的 `.sql` 文件，内容同样要可重复执行。
3. 只属于全新安装基础表的改动，再同步到 `gost.sql`。

## 自动校验

`scripts/check-schema-sources.py` 会在每次发布前运行：如果某张表只出现在迁移脚本里，而启动建表和 `gost.sql` 都没有它，发布会失败。这种情况意味着这张表只存在于手动迁移过的数据库上。

本地运行：

```bash
python3 scripts/check-schema-sources.py
```

目前有一部分表只有启动建表、没有对应的迁移脚本，这是允许的，校验只会列出数量，不会报错。
